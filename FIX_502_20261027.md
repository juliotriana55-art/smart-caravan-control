# Staging 5.2.1 — immediate 502 connection failure

## Observed
The iPhone screenshot showed `VRM HTTP 502`. Site Worker logs recorded repeated GET `/staging-vrm/api/victron/diagnostics` returning 502 with 0–1 ms execution around 23:53 Melbourne on 27 October 2026. No uncaught Worker exception was reported because the bridge caught the failure and replaced it with a generic response.

## Root defect and correction
The bridge passed `redirect: 'error'` to fetch. Cloudflare Workers/workerd implements only `manual` and `follow`; `error` throws immediately during Request construction, before a network request is made. Replaced it with `manual` and explicitly reject all 3xx responses. A private header is never forwarded to a redirect Location. Production main and worker.js remain unchanged.

Primary evidence:
- https://developers.cloudflare.com/workers/runtime-apis/request/ — redirect options and lack of error mode.
- https://github.com/cloudflare/workerd/blob/main/src/workerd/api/http.c%2B%2B — Request::tryParseRedirect and the runtime restriction.

## Diagnostics improvement
The bridge returns bounded codes for known key, configuration, Victron permission, timeout and upstream failures. Arbitrary upstream bodies and exception messages are neither displayed nor logged. Logs contain stage, code and HTTP status only. The frontend shows an English/Spanish explanation in Settings and diagnostic fields instead of discarding every cause behind a generic 502.

## Verification
- 130 Node tests and 14 Python checks passed; runtime scenarios passed. Actual logs in test-results/*20261027.txt.
- Added a Worker-compatible fetch fixture that rejects unsupported redirect modes. The old implementation fails it; the fixed implementation reaches the upstream handler successfully.
- Verified that redirects are blocked without following or reflecting Location/key values, and upstream errors preserve only known safe causes.
- The production Worker `/health` returned HTTP 200 with version 0.4.2 and Victron configured. This only verifies server reachability/configuration presence.
- A live HTTP call from the generated gateway module, executed in Node with a deliberately invalid dummy key, reached the actual read-only diagnostics route and returned HTTP 401 / APP_KEY_REJECTED as expected. No real credentials or telemetry were used. This is not an authenticated request through the private deployed Site and does not verify caravan readings.
